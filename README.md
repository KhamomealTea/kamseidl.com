# kamseidl.com (self-hosted)

Your site, as plain static files. No Wix, no monthly fee, no platform limits.

## What's here

| File | What it is |
|---|---|
| `index.html` | The portfolio: Work, Bio, case studies, Resume, Contact |
| `blog.html` | The blog: index, category pages, and posts. Separate on purpose |
| `blog-admin.html` | Write and edit blog posts in your browser |
| `content/posts.js` | Your blog posts. The admin page generates this file |
| `content/resume.js` | Your resume content. Edit this file directly |
| `_ds/` | Fonts, colors, and components (the Crucible design system) |
| `videos/` | Case study clips (Crucible, Paladins, Smite 2, Wizard of Oz) |
| `images/` | Crucible and VCS screenshots |
| `support.js` | Runtime the pages need. Don't edit |

Pages are addressed by hash, so everything works with no server config.

Portfolio: `#/`, `#/bio`, `#/work/crucible`, `#/work/vcs`, `#/work/paladins`,
`#/work/smite-2`, `#/work/woz-magic-match`, `#/ui-design`, `#/resume`. Contact is a mailto
link, not a page.

Blog (its own file): `#/`, `#/<post-slug>`, `#/cat/<category>`.

The UI Design page and the blog are currently **hidden**. Both still work at their URLs
(`index.html#/ui-design` and `blog.html`), but their footer links are commented out in
`index.html` so a recruiter sees only work and resume. Search the footer for "Hidden for now"
and uncomment the two lines to bring them back.

## Working in VS Code + git

There is no build step. Open the folder in VS Code and edit the HTML directly, the files you
ship are the files you edit.

```bash
cd path/to/this/folder
git init
git add .
git commit -m "Portfolio site"
git branch -M main
git remote add origin https://github.com/KhamomealTea/kamseidl.com.git
git push -u origin main
```

**To preview locally**, don't open the file with File → Open. The pages fetch `support.js`,
`content/`, and `_ds/`, and browsers block those over `file://`. Use a local server instead:

- **VS Code Live Server extension** (easiest), right-click the HTML file → "Open with Live Server"
- or `python -m http.server 8000`, then visit `http://localhost:8000`

Where things live:

- **Copy and layout** are inline in `index.html`. The template is the markup at the
  top; the logic class near the bottom holds routing, the theme toggle, and the video clip loop.
- **Colors, type, spacing** are CSS custom properties from `_ds/`. Prefer changing a `var(--*)`
  value over hardcoding a hex.
- **Resume content** is data in `content/resume.js`, not markup.
- **Blog posts** are data in `content/posts.js`, generated by `blog-admin.html`.

Videos use `data-clip-start` / `data-clip-end` attributes to loop a window of a longer file.
Change those numbers to retime a clip, no re-encoding needed.

Once it's on GitHub, Netlify and Cloudflare Pages can both deploy on push, so publishing
becomes `git push` instead of a drag-and-drop.

## Hosting

**Use Netlify Drop.** It's free for a site this size, it needs no terminal and no git, and it
handles HTTPS and your custom domain for you.

1. Go to `app.netlify.com/drop`.
2. Drag this whole folder onto the page. It's live in about 20 seconds at a temporary URL.
3. Create a free account when it prompts you, so the site sticks around.
4. In **Site configuration → Domain management**, add `kamseidl.com` and `www.kamseidl.com`.
   Netlify shows you the DNS records to set.
5. Point your domain at Netlify, either move the domain's nameservers to Netlify, or add the
   records Netlify gives you at your current registrar. **Do this before you cancel Wix**, and
   keep Wix active for a day or two after so there's no gap.
6. To update the site later, drag the folder onto the same site's **Deploys** tab.

Cloudflare Pages and Vercel work the same way if you'd rather use those. Any plain web host
(cPanel, S3) also works. Just upload the folder; there is nothing to build or compile.

### GitHub Pages
The repo `KhamomealTea/kamseidl.com` is set up for this. In the repo, go to
**Settings → Pages → Source: Deploy from a branch**, branch `main`, folder `/ (root)`.
It publishes at `https://khamomealtea.github.io/kamseidl.com/` in about a minute, and you can
add `kamseidl.com` as a custom domain on the same screen.

**The repo has to be public for Pages to work on a free account.** Settings → General → bottom
of the page → Change visibility. If you'd rather keep it private, use Netlify instead, it
deploys private repos on the free tier.

Keep every file in the same folder as `support.js`, `content/`, and `_ds/`.

### The one thing to update when your domain changes
Link previews (LinkedIn, Slack, iMessage) need **absolute** URLs, so three tags are hardcoded to
`https://khamomealtea.github.io/kamseidl.com`. When `kamseidl.com` goes live, find-and-replace
that string with `https://kamseidl.com` across `index.html` and `blog.html` — it appears in
`og:image` and `og:url` in each. Nothing else in the site depends on an absolute URL. If you
skip it, the pages still work; the share card just shows a blank image well.

## Publishing a blog post

1. Open `blog-admin.html`.
2. Write the post. It saves in your browser as you type, so you can close the tab.
3. Click **Download posts.js**.
4. Replace `content/posts.js` with the downloaded file.
5. Re-upload the folder to Netlify.

Post body accepts simple markdown: `## heading`, `- list item`, `**bold**`, `*italic*`,
`[link](url)`, `![alt](image-url)`.

## Editing the resume

Open `content/resume.js` in any text editor. The comments mark what still needs filling in:
dates for each role, and the Caesars / Scientific Games entries. Anything left blank simply
doesn't appear on the page, so there's no risk of publishing a placeholder.

The Resume page has a **Print / save as PDF** button, that's the PDF you send recruiters, and
it always matches the live page.

## Images

Right now the images still load from your Wix media URLs (`static.wixstatic.com`). **Those stop
working when you cancel Wix.** Before you cancel:

1. Download your media library from Wix (Site Media → select all → download).
2. Put the files in an `images/` folder next to the site file.
3. Find-and-replace each `https://static.wixstatic.com/media/...` URL with `images/your-file.jpg`.

There are about 30 of them, in `index.html` and `content/posts.js`.
